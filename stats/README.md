# 내려받기 수 기록

GitHub 은 릴리스 자산의 **누적** 내려받기 수만 알려 준다. 언제 받았는지,
몇 명이 받았는지는 주지 않는다. (같은 사람이 두 번 받으면 2로 잡힌다.)

그래서 `.github/workflows/download-stats.yml` 이 **하루 한 번**(00:07 KST)
그 순간의 숫자를 `downloads.json` 에 적어 둔다. 이웃한 두 날의 차이가
그날 받아간 수다.

```
11-14  한글 4
11-15  한글 7   →  11월 15일에 3개
```

## 알아 둘 것

- **과거는 되살릴 수 없다.** 기록을 시작한 날부터만 쌓인다.
- GitHub 의 예약 실행은 붐빌 때 **밀리거나 걸러질 수 있다.** 빠진 날은
  빈 칸으로 남고, 그 다음 날 차이에 합쳐져 보인다.
- 릴리스 자산을 **교체하면 그 자산의 숫자는 0 으로 돌아간다.** 그날 차이가
  음수로 나오면 대개 그 일이 있었던 것이다. `assets` 항목을 보면 어느
  파일이 바뀌었는지 알 수 있다.
- 60일 동안 저장소에 아무 활동이 없으면 GitHub 이 예약 실행을 멈춘다.
  이 워크플로는 매일 커밋을 하므로 스스로 활동을 만든다.
- 읽는 저장소는 스크립트 맨 위 `REPOS` 에 있다. 못 읽는 저장소는 건너뛰고
  나머지만 기록한다.
